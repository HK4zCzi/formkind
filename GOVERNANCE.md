# Governance

FormKind currently uses a maintainer-led model.

## Roles

- **Users** use the project and provide feedback.
- **Contributors** submit issues, documentation, tests, or code.
- **Reviewers** are trusted contributors who regularly review a project area.
- **Maintainers** can merge changes, manage releases, respond to security reports, and set project direction.

The founding maintainer is [Ho Viet Khanh (`@HK4zCzi`)](https://github.com/HK4zCzi).

## Decisions

Routine changes are decided in pull requests. Changes to rule semantics, public APIs, governance, or security posture require a public proposal and at least seven days for community feedback once the project has regular contributors. The maintainer documents the final decision and tradeoffs.

No automated tool can merge or publish a release. AI-assisted review is advisory and must be checked by a human maintainer.

## Becoming a maintainer

A contributor may be invited after a sustained record of high-quality work, constructive reviews, sound security judgment, and alignment with the project's international-user mission. Maintainer access follows least privilege and can be removed after six months of inactivity or for a Code of Conduct/security violation.

As the team grows, governance will move to multi-maintainer approval for releases and sensitive changes.
